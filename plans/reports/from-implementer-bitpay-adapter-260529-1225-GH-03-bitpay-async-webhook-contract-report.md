# Implementation Report — BitPay adapter (V3 Phase 02) + async webhook contract

**Date:** 2026-05-29 | **Branch:** feat/v3-phase-03-nowpayments-adapter | **Scope:** Phase 02

## What shipped
New package `@vibecc/paykit-bitpay` + an additive async-webhook hook on the core adapter contract.

### Core contract (additive, non-breaking)
- `PaymentProviderAdapter.resolveWebhook?(rawBody, headers): Promise<NormalizedWebhookEvent|null>` — optional. Existing 7 adapters untouched (undefined → keep sync path). `packages/core/src/adapters/adapter.ts`.
- Router (`packages/server/src/routes/webhooks/webhook-router.ts`): if `resolveWebhook` present, await it instead of the sync `verifyWebhookSignature`+`parseWebhookPayload` pair. Throw → 502 (provider retries). Everything downstream (dedup, SELECT FOR UPDATE, ledger, status) unchanged.

### BitPay adapter design (driven by research, NOT assumption)
- **BitPay does NOT sign IPNs** (official docs). The POSTed body is an untrusted trigger. Auth = **fetch-back**: `resolveWebhook` parses the invoice id, calls `GET /invoices/:id`, and trusts ONLY the API response. Sync `verifyWebhookSignature`/`parseWebhookPayload` are fail-closed (false/null) so the sync path can never credit on unverified data.
- **Facade split:** invoice-create + fetch-back use the POS token (zero crypto, fully tested). Refund (`POST /refunds`) + listing require BitPay's MERCHANT facade = ECDSA secp256k1. That signer is INJECTED via `BitpayMerchantSigner` (DI) so the package keeps zero runtime deps and ships NO unverified crypto. No signer → refund returns `failed{NO_MERCHANT_SIGNER}`, fetchTransactions returns `[]`.
- Status map: confirmed/complete → completed; expired → expired; invalid → failed; new/paid → null (in-flight). `exceptionStatus=paidPartial` → underpaid; >5bps drift → amount_mismatch (parity w/ NowPayments Val D3).
- Refund returns `state:'pending_webhook'` (reuses Phase-01 infra + migration 011 enum; no new migration, no server/core change beyond the shared async hook).
